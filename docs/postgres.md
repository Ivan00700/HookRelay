# PostgreSQL

Docker Compose запускает PostgreSQL 17 отдельно от HTTP-сервиса. Имена пользователя и базы — `hookrelay`. HTTP API и воркеры используют `PostgresStore`, а `dbcheck` проверяет доступность PostgreSQL через `pgx`. Для обеих команд нужна `DATABASE_URL`.

## Запуск базы

Требуются Docker Desktop с Linux-контейнерами и Docker Compose.

При первом запуске скопируйте `.env.example` в `.env` и задайте свой пароль. Если `.env` уже существует, сохраните его значения. Пример содержимого:

```dotenv
POSTGRES_PASSWORD=replace-with-a-local-password
POSTGRES_PORT=5433
```

`.env` исключён из Git. Compose читает его автоматически при запуске из корня проекта.

```powershell
docker compose up -d --wait db
docker compose ps
```

Ожидаемый статус — `healthy`. Адрес для программ на компьютере: `127.0.0.1:5433`. Внутри контейнера PostgreSQL слушает `5432`; публикация порта соединяет эти два адреса. Другой внешний порт можно задать через `POSTGRES_PORT`.

Данные расположены в именованном томе `postgres_data`. `docker compose down` удаляет контейнер и сеть, сохраняя этот том. Флаг `-v` удаляет том вместе с данными. Смена внешнего порта не изменяет содержимое тома. Значения `POSTGRES_USER`, `POSTGRES_DB` и `POSTGRES_PASSWORD` инициализируют пустой том; изменение пароля в `.env` не меняет пароль уже созданного пользователя БД.

## Таблицы и SQL-файлы

| Файл | Таблица | Назначение |
| --- | --- | --- |
| `001_init.sql` | `endpoints` | Адреса получателей и их секреты |
| `002_create_events.sql` | `events` | События, JSON-тела и статусы |
| `003_create_delivery_attempts.sql` | `delivery_attempts` | Номера попыток, время выполнения, HTTP-коды и ошибки |
| `004_event_queue.sql` | `events` | Срок и номер аренды задания, индексы очереди |
| `005_delivery_retries.sql` | `events` | Общий счётчик попыток, счётчик текущего цикла, время следующей отправки |

SQL-файлы применяются вручную, по порядку и один раз для каждой базы. Автоматического учёта применённых миграций в проекте нет. Повторный `CREATE TABLE` сообщает об уже существующей таблице.

Для пустой базы выполните все пять файлов:

```powershell
Get-Content -Raw migrations/001_init.sql,migrations/002_create_events.sql,migrations/003_create_delivery_attempts.sql,migrations/004_event_queue.sql,migrations/005_delivery_retries.sql | docker compose exec -T db psql -U hookrelay -d hookrelay -v ON_ERROR_STOP=1 --single-transaction -f -
```

`ON_ERROR_STOP=1` останавливает выполнение при ошибке. `--single-transaction` применяет весь переданный SQL в одной транзакции: при ошибке изменения этой команды откатываются. `-f -` читает SQL из стандартного ввода.

Для обновления базы, в которой уже применены файлы `001`–`004`, остановите старую версию приложения и примените пятый файл один раз:

```powershell
Get-Content -Raw migrations/005_delivery_retries.sql | docker compose exec -T db psql -U hookrelay -d hookrelay -v ON_ERROR_STOP=1 --single-transaction -f -
```

Если применены только `001`–`003`, сначала аналогично примените `004_event_queue.sql`, затем `005_delivery_retries.sql`. Пятый файл восстанавливает общий счётчик из существующей истории, чтобы новые попытки не конфликтовали по номеру; старые записи сохраняются.

Таблица `events` ссылается на `endpoints`, а `delivery_attempts` — на `events`. `ON DELETE RESTRICT` запрещает удалять запись, на которую ссылается история. Для события уникальна пара `(event_id, attempt_number)`; время завершения и результат запроса могут отсутствовать.

## DBeaver

Создайте подключение PostgreSQL со следующими значениями:

| Параметр | Значение |
| --- | --- |
| Host | `127.0.0.1` |
| Port | `5433` или значение `POSTGRES_PORT` |
| Database | `hookrelay` |
| User | `hookrelay` |
| Password | Значение `POSTGRES_PASSWORD` из `.env` |

Для подключения, настроенного на порт `5432`, измените Port на `5433` и переподключитесь. Таблицы находятся в схеме `public`. Для просмотра структуры обновите список таблиц после применения SQL-файлов.

## Проверка соединения из Go

Команда читает строку подключения из `DATABASE_URL`. Go не загружает `.env` автоматически. В PowerShell задайте переменную для текущего терминала, подставив пароль из `.env`:

```powershell
$databasePassword = [uri]::EscapeDataString('пароль из POSTGRES_PASSWORD')
$env:DATABASE_URL = "postgres://hookrelay:${databasePassword}@127.0.0.1:5433/hookrelay?sslmode=disable"
go run ./cmd/dbcheck
```

`EscapeDataString` кодирует специальные символы пароля для URL. При изменении `POSTGRES_PORT` подставьте тот же порт в строку подключения. `sslmode=disable` используется для локальной базы в этом Compose-окружении.

Успешный запуск выводит имя базы, пользователя и версию PostgreSQL. Команда ограничивает проверку пятью секундами; при ошибке завершается с ненулевым кодом. Ошибки разбора строки подключения выводятся без её содержимого.

Для запуска HTTP API используйте ту же переменную окружения:

```powershell
go run ./cmd/hookrelay
```

Приложение проверяет подключение и наличие полей очереди до запуска HTTP-сервера. SQL-файлы должны быть применены заранее: автоматического создания таблиц при старте нет. Контексты запросов к хранилищу из HTTP API ограничены пятью секундами. При остановке HTTP-сервер завершает запросы, воркеры прекращают захват новых заданий и завершают активные отправки, затем закрывается пул PostgreSQL. Оставшиеся pending доступны следующему экземпляру приложения.

Очередь находится в `events`. После INSERT событие pending доступно любому воркеру, когда наступит `next_attempt_at`. В транзакции `FOR UPDATE SKIP LOCKED` выбирает свободную строку, переводит её в processing, увеличивает lease_version и счётчики попыток, устанавливает lease_until на 30 секунд и создаёт запись в delivery_attempts. HTTP выполняется после COMMIT. Завершение в одной транзакции записывает время, HTTP-код и ошибку попытки, затем меняет статус события. Обе записи защищены проверкой версии и действующего срока аренды; при ошибке транзакция откатывается целиком.

При аварии истёкшая аренда позволяет другому воркеру повторно захватить событие. Processing без lease_until от старой версии также подхватывается. Запуск нового экземпляра не обнуляет аренды работающих воркеров. После завершения старый владелец не может перезаписать результат нового.

Захват ограничен пятью секундами, обработка задания — десятью, запись результата — ещё пятью. HTTP-запрос Sender имеет собственный таймаут три секунды. При пустой очереди или ошибке БД воркер ждёт 250 мс и пробует снова. Аренда в 30 секунд превышает эти лимиты обычной обработки.

Восстановление после аварии может повторить уже полученный HTTP-запрос. Для защиты от дублей получатель может хранить `X-HookRelay-Event-ID`. История прерванной попытки закрывается при следующем захвате с ошибкой `delivery interrupted: lease expired`, без HTTP-кода. Каждый захват расходует попытку; после четырёх прерванных захватов событие получает failed.

Сетевые ошибки, таймауты, `408`, `429` и `5xx` приводят к повтору через 5 секунд, 30 секунд и 2 минуты после предыдущего результата. Всего в цикле четыре попытки. Другие ответы вне `2xx` завершают цикл сразу. Задержка хранится как дата в `next_attempt_at`; воркер не занимает goroutine ожиданием отдельного события. Перезапуск сохраняет расписание. Фиксированные интервалы не учитывают `Retry-After`.

`attempt_count` хранит общий номер за всё время, а `cycle_attempts` — число захватов в текущем цикле. `POST /api/v1/events/{id}/retry` разрешён только для failed: он переводит событие в pending, сбрасывает только счётчик цикла и назначает отправку на текущее время. История, общий счётчик, ID и тело события сохраняются. Два одновременных запроса не создают два цикла: обновление допускает только один переход из failed. История доступна через `GET /api/v1/events/{id}/attempts`.

Пул соединений создаётся в `internal/postgres.Open`. Вызов `Ping` проверяет реальное соединение с сервером. Если проверка не удалась, функция закрывает пул; после успешного открытия за закрытие отвечает вызывающий код.

Для интеграционного теста используйте ту же локальную базу:

```powershell
$env:TEST_DATABASE_URL = $env:DATABASE_URL
go test ./... -run Integration -count=1 -v
```

Тесты проверяют соединение, SQL-файлы, ограничения, CRUD, HTTP API, два пула воркеров и восстановление очереди. Проверяются пропуск заблокированной строки, естественное истечение аренды, отказ запоздалому владельцу, атомарность истории и результата, лимит и ручной повтор. Тест реальной HTTP-доставки ждёт пятисекундный интервал; тесты длинных интервалов проверяют сохранённую дату и сдвигают только свои тестовые задания, чтобы не ждать две минуты. Тест аварии запускает отдельный процесс, прерывает его во время HTTP-отправки и проверяет восстановление события. Чтобы этот тест не ждал 30 секунд, срок только его тестовой аренды сдвигается в прошлое.

Временные схемы откатываются или удаляются после тестов; таблицы приложения и их данные не изменяются. Пользователю тестовой базы нужно право создавать схемы. Без TEST_DATABASE_URL интеграционные тесты пропускаются.

Удалить переменные из текущего терминала можно так:

```powershell
Remove-Item Env:DATABASE_URL,Env:TEST_DATABASE_URL -ErrorAction SilentlyContinue
```
