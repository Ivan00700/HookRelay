# Развёртывание

## Docker Compose

Нужен Docker Desktop с Linux-контейнерами либо Docker Engine с Compose. Go на компьютере для этого варианта не требуется.

```powershell
git clone https://github.com/Ivan00700/HookRelay.git
cd HookRelay
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
```

Задайте свой POSTGRES_PASSWORD в `.env`. Затем:

```powershell
docker compose up -d --build --wait
docker compose ps
curl.exe -i http://localhost:8080/ready
```

Ожидаются healthy у app и db, ответ `/ready` со статусом 200. Панель находится на `http://localhost:8080/`. Для другого внешнего порта укажите HTTP_PORT в `.env`.

Dockerfile собирает четыре бинарника с CGO_ENABLED=0 в образе Go 1.26 и переносит их в Alpine 3.23 с CA-сертификатами. В рабочем образе нет компилятора Go; процесс работает от пользователя hookrelay. Интерфейс встроен в бинарник приложения. `.env`, `.git`, черновики и локальная документация исключены из контекста сборки.

## Подключения и данные

| Откуда | Адрес |
| --- | --- |
| Браузер → приложение | `127.0.0.1:8080` или HTTP_PORT |
| DBeaver → PostgreSQL | `127.0.0.1:5433` или POSTGRES_PORT |
| Приложение → PostgreSQL | `db:5432` |
| Prometheus → приложение | `app:8080` |
| Приложение → получатель профиля demo | `receiver:9000` |

`localhost` внутри контейнера означает сам контейнер. Поэтому в endpoint для демонстрации нужен адрес `http://receiver:9000/webhook`, а не localhost:9000.

Compose передаёт параметры подключения без пароля в DATABASE_URL, пароль отдельно через PGPASSWORD. Его читает pgx; символы `@`, `:` или `%` в пароле не требуют URL-кодирования в этом варианте. Compose подставляет значения из `.env`; не публикуйте результат `docker compose config` с раскрытым окружением.

Схема создаётся официальным образом PostgreSQL: файлы migrations/*.sql смонтированы в `/docker-entrypoint-initdb.d` только для чтения. Они выполняются по имени **только при инициализации пустого postgres_data**. Проверка db использует TCP, чтобы app не стартовало во время временного сервера инициализации.

Для уже существующего тома SQL автоматически не запускается. Если все пять файлов уже применены, приложение использует текущие таблицы. При неполной схеме сначала примените недостающие SQL по [инструкции PostgreSQL](postgres.md). Приложение не выполняет миграции при каждом старте и не ведёт таблицу их версий.

Перезапуск и остановка:

```powershell
docker compose restart app
docker compose down
docker compose up -d --wait
```

`down` сохраняет именованные тома. Флаг `-v` удаляет их данные. Для обновления кода используйте `docker compose up -d --build --wait`; перед изменением схемы сделайте резервную копию БД и остановите приложение. При сбое первой инициализации проверьте логи db и состояние схемы: повторный запуск непустого тома не применит пропущенные SQL.

Compose даёт приложению 30 секунд на остановку. SIGTERM запускает завершение HTTP-обработчиков и активных доставок. При принудительном завершении обработка восстанавливается после аренды; возможны дубликаты.

## Получатель и мониторинг

```powershell
docker compose --profile demo --profile monitoring up -d --build --wait
docker compose logs --tail 30 app receiver
```

Секрет профиля demo берётся из WEBHOOK_SECRET, по умолчанию dev-secret. Получатель доступен только в сети Compose. Проверяет HMAC и отвечает 204; бизнес-операции и дедупликация в нём не реализованы. Параметр RECEIVER_ADDR позволяет менять адрес прослушивания; для обычного запуска Go значение по умолчанию 127.0.0.1:9000.

Prometheus опубликован на localhost:9090. [Описание метрик](observability.md).

## Запуск из Go

Для разработки нужен Go 1.24+. Запускайте контейнер только с БД:

```powershell
docker compose up -d --wait db
$databasePassword = [uri]::EscapeDataString('пароль из POSTGRES_PASSWORD')
$env:DATABASE_URL = "postgres://hookrelay:${databasePassword}@127.0.0.1:5433/hookrelay?sslmode=disable"
go run ./cmd/dbcheck
go run ./cmd/hookrelay
```

Если контейнер app уже занимает 8080, сначала остановите его через `docker compose stop app` или выберите другой HTTP_PORT для Go-процесса. Go сам не читает `.env`. Переменная PGPASSWORD нужна в контейнере, а в показанном URL пароль указан явно.

Свой получатель можно поднять через `go run ./examples/receiver`, предварительно задав WEBHOOK_SECRET. Если получатель работает на компьютере, а приложение в Docker Desktop, нужен доступный контейнеру адрес и подходящий RECEIVER_ADDR. Для проверки без настройки сетевого доступа проще использовать профиль demo.

## Условия эксплуатации

Публикуемые Compose порты привязаны к 127.0.0.1. API не имеет аутентификации, TLS и ограничений частоты запросов. Конфигурация предназначена для доверенного локального окружения. Перед внешней эксплуатацией отдельно решаются доступ, транспортное шифрование, резервное копирование и хранение секретов.
