# HookRelay

**Асинхронная доставка webhook-событий с очередью в PostgreSQL, повторами и HMAC-подписью.**

Зарегистрируйте адрес получателя, отправьте событие и отслеживайте результат через REST API или веб-панель. Сервис сохраняет события до отправки, доставляет их параллельно и хранит историю каждой попытки.

[Запуск](#запуск) · [API](docs/api.md) · [Архитектура](docs/architecture.md) · [Проверки](docs/testing.md)

## Стек

| Область | Технологии |
| --- | --- |
| Backend | Go 1.24+, стандартный `net/http`, `context`, goroutine и `sync` |
| Хранилище и очередь | PostgreSQL 17, `pgx/v5`, SQL-миграции, транзакции и `FOR UPDATE SKIP LOCKED` |
| Подпись webhook | HMAC-SHA256, `crypto/hmac`, `crypto/sha256` |
| Веб-панель | HTML, CSS, JavaScript без фреймворков, файлы встроены через `go:embed` |
| Наблюдаемость | JSON-логи `log/slog`, request ID, Prometheus и `client_golang` |
| Окружение | Docker Compose для PostgreSQL и Prometheus |
| Проверки | `testing`, `httptest`, интеграционные тесты PostgreSQL, race detector, `go vet` |

## Возможности

- **REST API** — создание, чтение и удаление endpoints, приём событий, статусы и история попыток. Валидация JSON, обязательных полей и HTTP(S) URL; лимит тела запроса 1 MiB.
- **Устойчивая очередь** — события хранятся в PostgreSQL, два воркера забирают их с арендой на 30 секунд. Версия аренды защищает результат от устаревшего владельца; после аварии обработка восстанавливается.
- **Доставка и повторы** — HTTP POST с таймаутом 3 секунды, без перехода по редиректам. Первая отправка и три повтора через 5 секунд, 30 секунд и 2 минуты при сетевой ошибке, таймауте, `408`, `429` или `5xx`.
- **История и ручной повтор** — время, HTTP-код и ошибка каждой попытки. Повтор из `failed` начинает новый цикл, сохраняя ID события и историю.
- **HMAC-подпись** — тело подписывается секретом endpoint. Секрет не возвращается в API; в `examples/receiver` есть получатель с проверкой подписи.
- **Веб-панель** — создание endpoints, отправка событий, статусы, просмотр тела и попыток, ручной повтор и автообновление раз в три секунды.
- **Диагностика** — JSON-логи с `X-Request-ID`, `/health`, `/ready` и `/metrics`: приём и доставка, HTTP-запросы, длительность запросов и размер очереди.
- **Штатная остановка** — сервер завершает обработчики и активные отправки перед закрытием соединений с БД.

```text
REST API / веб-панель → PostgreSQL: pending
                              ↓
                   worker: захват и аренда
                              ↓
                HTTP POST + HMAC → получатель
                              ↓
          история + delivered / failed / pending с датой повтора
```

Веб-панель открывается на главной странице: формы создания endpoint и отправки события, таблица статусов, просмотр тела и истории попыток. Неуспешное событие можно отправить повторно; данные обновляются автоматически.

## Запуск

Для запуска нужен Docker с Compose. Команды рассчитаны на PowerShell.

```powershell
git clone https://github.com/Ivan00700/HookRelay.git
cd HookRelay
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
```

Задайте `POSTGRES_PASSWORD` в `.env`, затем соберите и запустите сервис:

```powershell
docker compose up -d --build --wait
```

Откройте **[localhost:8080](http://localhost:8080/)**. Compose запустит PostgreSQL, создаст таблицы в пустом томе и дождётся готовности приложения. Данные сохраняются в `postgres_data` при перезапуске. Внешние порты задаются через `HTTP_PORT` и `POSTGRES_PORT` в `.env`.

Для пробной доставки добавьте получателя:

```powershell
docker compose --profile demo up -d --build --wait
```

В панели создайте endpoint `http://receiver:9000/webhook` с секретом `dev-secret` (или своим `WEBHOOK_SECRET` из `.env`) и отправьте JSON-объект. Успешная доставка получает статус `delivered`. Генератор небольшой нагрузки:

```powershell
docker compose exec app /app/loadgen -endpoint-url http://receiver:9000/webhook -secret dev-secret -count 100 -concurrency 4
```

Он выводит JSON с числом принятых, отклонённых, доставленных и незавершённых событий. [Запуск, обновление и работа без контейнера приложения](docs/deployment.md), [сценарий демонстрации](docs/demo.md).

Prometheus запускается отдельно:

```powershell
docker compose --profile monitoring up -d --wait prometheus
```

Откройте [localhost:9090](http://localhost:9090/). Prometheus обращается к `app:8080` внутри Compose; настройка и PromQL приведены в [наблюдаемости](docs/observability.md).

## Проверки

```powershell
# задайте TEST_DATABASE_URL согласно docs/testing.md
./scripts/check.ps1
```

Скрипт выполняет тесты, повторный прогон с `-race` и покрытием, `go vet` и сборку. Интеграционные тесты создают отдельные временные схемы. Для проверки без PostgreSQL — `./scripts/check.ps1 -Unit`; интеграционные тесты будут пропущены. [Сценарии и команды](docs/testing.md).

## Ограничения

- Возможна повторная доставка после аварии или потери записи результата. Получателю нужна дедупликация по `X-HookRelay-Event-ID`, если повторная обработка недопустима.
- После четырёх неудачных попыток цикл завершается `failed`. Захват задания расходует попытку даже при аварии до отправки. Расписание переживает перезапуск; `Retry-After` не меняет фиксированные интервалы.
- HMAC подписывает только тело, не шифрует его и не защищает от повторного воспроизведения запроса. ID события не подписан; секрет хранится в БД открытым текстом.
- API без аутентификации и TLS, сервер слушает все интерфейсы. Запуск рассчитан на доверенную среду.
- Списки возвращаются целиком, без пагинации. Счётчики метрик сбрасываются при перезапуске процесса; состояние очереди читается из БД.
